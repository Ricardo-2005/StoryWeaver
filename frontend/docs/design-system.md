# StoryWeaver Phase 0 设计系统

设计来源：`StoryWeaver_CODEX_前端设计文档_龙族模板演示版_V1.3.md`。

## 原则

- 低装饰、内容优先、宽留白；不使用仿古纹理或霓虹 AI 控制台风格。
- 界面强调色为墨绿色；浅色使用纸张底，深色使用夜写底。
- 4px 间距网格，控件 6px、卡片 10px、Dialog 12px 圆角。
- 状态不能只靠颜色表达；所有交互都必须有可见焦点。
- 尊重 `prefers-reduced-motion`。

## Token 文件

- `src/styles/tokens.css`：字体、间距、圆角、语义状态。
- `src/styles/theme-light.css`：浅色纸张主题。
- `src/styles/theme-dark.css`：深色夜写主题。
- `src/styles/element-overrides.css`：Element Plus 语义变量映射。

主题偏好由 Pinia 管理，可选 `light / dark / system`。只有主题偏好写入 localStorage；鉴权 Token 不持久化。

## 排版与层级

- 页面只保留一个主标题，标题用于路由焦点恢复。
- 正文和说明文字使用语义色变量，不直接写灰色常量。
- 表单标签必须持续可见，placeholder 只能提供示例，不能代替标签。
- 密集生产工具优先使用清楚的分组、分隔线和短说明，不依赖大面积装饰卡片。

## 组件语义

| 类型 | 用途 | 约束 |
| --- | --- | --- |
| Primary Button | 当前流程唯一主要动作 | 同一区域避免多个主按钮竞争 |
| Secondary Button | 次要动作、打开设置 | 深浅主题都必须达到文字对比度 |
| Danger Button | 归档、停止等高风险动作 | 文字说明必须明确具体结果 |
| Text Button | 恢复推荐、清空等轻量动作 | 不能仅依靠低对比度颜色表达可点击性 |
| Status Badge | 推荐/已修改/状态机状态 | 同时输出文字，不只显示颜色 |
| Problem Alert | 后端 Problem Details | 展示稳定摘要，不能泄露堆栈和密钥 |

## 表单与动态推荐

Skill 熔炉中的推荐模板遵循以下设计规则：

1. 素材标签和 Skill 类型都选择后才显示推荐内容。
2. “推荐内容”和“已修改”使用文字徽标区分。
3. 用户修改过的字段不会被选项切换静默覆盖。
4. 每个字段可以单独“恢复推荐内容”。
5. 切换模板遇到已修改内容时，提供“保留当前内容”和“使用新模板”的显式选择。
6. 上传区域同时显示文件数量、单文件上限、总量和支持编码。

## 可访问性

- 所有可交互元素可通过键盘访问，Dialog 打开后焦点进入，关闭后返回触发按钮。
- 页面提供“跳到主要内容”链接，路由切换后主标题获得焦点。
- 浅色、深色及主题切换过程均接受 axe WCAG 2.2 A/AA 检查。
- 主题切换时文字、背景和边框语义色即时改变，避免动画中间帧产生低对比度。
- `prefers-reduced-motion` 下关闭非必要动画；状态变化仍通过文字表达。

## 响应式原则

- 桌面端保留侧栏和生产工具密度；移动端将侧栏改为可关闭导航层。
- 表单双列在窄屏自动回落为单列，操作按钮允许换行但保持主要动作优先。
- 文件名、项目名和长状态文本必须允许截断或换行，不能撑破容器。

## 验证

设计系统不只依靠截图人工判断。当前使用 Playwright 视觉基线、axe、键盘测试、移动端视口和性能预算共同验收；设计 Token 变化必须重跑相关基线，不能直接覆盖失败截图而不解释差异。
