# StoryWeaver 项目更新文档  
## Skill 熔炼：素材标签 × Skill 类型动态模板联动

> 文档用途：交给 Codex / 开发人员直接更新现有 StoryWeaver 项目  
> 更新范围：Skill 熔炼页面  
> 核心目标：根据“素材标签”和“Skill 类型”自动切换「希望重点学习什么」与「素材说明」默认模板

---

## 1. 更新背景

当前 Skill 熔炼页面已经包含两个关键选择项：

### 素材标签

- 正文
- 对话
- 人物
- 描写
- 大纲
- 写作规范
- 其他

### Skill 类型

- 基础写作
- 题材方法
- 写作技法
- 审查规则

页面后续还有：

- 希望重点学习什么
- 素材说明

现状问题是：

> 无论前面选择什么素材标签和 Skill 类型，后面的两个输入框缺少有针对性的默认内容。

这会导致用户仍然需要自己理解 Skill 熔炼逻辑并填写大量提示词，也会降低熔炼结果的稳定性。

本次更新要求将前两个选择项与后两个文本框联动。

---

# 2. 核心交互

最终逻辑：

```text
素材标签
    +
Skill 类型
    ↓
查询对应模板
    ↓
自动生成：
1. 希望重点学习什么
2. 素材说明
```

总组合数：

```text
7 个素材标签 × 4 个 Skill 类型 = 28 组模板
```

每一种组合必须拥有独立模板。

例如：

```text
正文 + 基础写作
```

应该重点分析：

- 章节结构
- 叙述
- 动作
- 对话
- 心理
- 场景衔接
- 基础节奏

而：

```text
正文 + 写作技法
```

应该重点分析：

- 信息差
- 留白
- 伏笔
- 延迟揭示
- 场景切换
- 情绪递进
- 章末悬念

两者不能使用同一套模板。

---

# 3. 页面交互要求

## 3.1 初始状态

如果用户还没有同时选择：

- 素材标签
- Skill 类型

则：

```text
希望重点学习什么
素材说明
```

显示普通 placeholder，不自动填充模板。

例如：

```text
希望重点学习什么：
请选择素材标签和 Skill 类型后自动生成建议内容。
```

```text
素材说明：
系统会根据素材类型生成对应说明，你也可以自行修改。
```

---

## 3.2 两项选择完成

当用户完成：

```text
素材标签 = 正文
Skill 类型 = 写作技法
```

立即读取：

```text
templateMap["正文"]["写作技法"]
```

并自动填充两个文本框。

---

## 3.3 用户可以修改

自动生成的内容只是默认建议。

必须允许用户：

- 删除
- 增加
- 修改
- 完全重写

最终提交时，应以文本框当前内容为准。

---

## 3.4 切换选项时的覆盖规则

防止用户已经修改内容后，被切换下拉框意外覆盖。

建议增加状态：

```ts
focusCustomized: boolean
descriptionCustomized: boolean
```

如果用户从未修改文本：

```text
切换标签 / 类型
→ 自动替换新模板
```

如果用户已经手动修改：

```text
切换标签 / 类型
→ 不立即覆盖
```

弹出轻量提示：

```text
当前内容已被修改，是否使用新的推荐模板？
```

按钮：

```text
保留当前内容
使用新模板
```

# 4. 模板数据结构

建议不要把模板硬编码在 Vue/React 页面组件中。

新增独立配置：

```text
src/
└── config/
    └── skillTemplateMap.ts
```

示例：

```ts
export interface SkillMeltTemplate {
  focus: string;
  description: string;
}

export type MaterialTag =
  | "正文"
  | "对话"
  | "人物"
  | "描写"
  | "大纲"
  | "写作规范"
  | "其他";

export type SkillType =
  | "基础写作"
  | "题材方法"
  | "写作技法"
  | "审查规则";

export const skillTemplateMap:
Record<MaterialTag, Record<SkillType, SkillMeltTemplate>> = {
  正文: {
    基础写作: {
      focus: `...`,
      description: `...`
    },
    题材方法: {
      focus: `...`,
      description: `...`
    },
    写作技法: {
      focus: `...`,
      description: `...`
    },
    审查规则: {
      focus: `...`,
      description: `...`
    }
  },

  对话: {
    // ...
  }
};
```

必须保证 28 个组合全部存在。

# 一、正文

## 正文 × 基础写作

### 希望重点学习什么

```text
重点学习这批正文素材中的基础小说写作能力。

请重点分析：
1. 章节如何开场、推进和收尾；
2. 叙述、动作、对话、心理和环境描写之间的比例；
3. 长短句与段落的组合方式；
4. 信息如何自然交代；
5. 如何通过行动推动剧情，减少直接解释；
6. 场景之间如何自然衔接；
7. 一章内部如何形成节奏起伏；
8. 如何维持阅读流畅度和连续性。

只提炼可以迁移到其他小说中的基础写作方法，不复制原文。
```

### 素材说明

```text
这是一批小说正文素材。

素材主要用于分析正文的基本组织方式，包括叙述、动作、对白、心理、环境、信息释放和章节结构。

请忽略具体人物姓名、地点、势力、世界观和剧情结果，只提炼能够复用于其他作品的基础写作规律。
```

```text

重点分析：

3. 如何避免连续长篇讲话；
4. 对话和动作、神态如何穿插；
5. 如何删除无意义寒暄；
6. 如何用对白推动事件；
7. 如何区分不同人物的说话习惯；
8. 对话标签应该如何控制。

最终形成自然、简洁、能够推进剧情的对白基础规则。
```

### 素材说明

```text
素材以人物对话及相关场景为主。

请重点观察对白长度、轮次、停顿、打断、动作插入与信息传递方式。

不要保留具体人物和原台词，只总结基础对白方法。
```

## 对话 × 审查规则

### 希望重点学习什么

```text
重点建立人物对白的自动审查规则。

检查：
1. 是否连续出现过长对白；
2. 是否所有人物口吻一致；
3. 是否出现无意义信息重复；
4. 是否大量使用“他说、她说”；
5. 是否频繁解释读者已经知道的信息；
6. 是否对白与人物身份不符；
7. 是否出现为了交代设定而强行聊天；
8. 是否缺少动作和场景反馈；
9. 是否对白轮次过长却没有事件推进；
10. 是否出现机械问答。

输出明确、可检测、可修改的对白审查规则。
```

### 素材说明

```text
素材用于建立人物对白质量审查标准。

重点关注自然度、角色差异、信息密度、节奏和剧情作用。

最终规则应可用于自动检查生成章节中的对白质量。
```

# 6. “当前题材”的来源

模板中不要让用户手动填写：

```text

```

系统应该尽量从当前项目读取，例如：

```json
{
  "genre": "仙侠"
}
```

如果项目类型是：

```text

```

则实际展示：

```text

```

而不是：

```text
重点学习【当前题材】中的人物说话方式。
```

读取优先级：

```text
项目题材
>
世界书中的题材定义
>
用户创建 Skill 时选择的题材
>
“当前题材”
```

# 10. 前端推荐实现

模板选择函数：

```ts
export function getSkillMeltTemplate(
  materialTag: MaterialTag,
  skillType: SkillType,
  genre?: string
): SkillMeltTemplate {

  const template = skillTemplateMap[materialTag]?.[skillType];

  if (!template) {
    return {
      focus: "",
      description: ""
    };
  }

  const currentGenre = genre?.trim() || "当前题材";

  return {
    focus: template.focus.replaceAll("当前题材", currentGenre),
    description: template.description.replaceAll(
      "当前题材",
      currentGenre
    )
  };
}
```

Vue 示例：

```ts
watch(
  [() => form.materialTag, () => form.skillType],
  ([tag, type]) => {
    if (!tag || !type) return;

    const template = getSkillMeltTemplate(
      tag,
      type,
      project.genre
    );

    if (!focusCustomized.value) {
      form.focus = template.focus;
    }

    if (!descriptionCustomized.value) {
      form.materialDescription = template.description;
    }
  }
);
```

# 14. 本次更新的最终目标

本次改动的核心不是单纯增加 28 段 placeholder。

而是建立：

```text
素材是什么
        ↓
这次想熔炼成什么 Skill
        ↓
应该从素材里观察什么
        ↓
应该如何解释这批素材
        ↓
应该输出什么结构
```

即：

```text
Material
    ↓
Material Tag
    ↓
Skill Type
    ↓
Dynamic Learning Template
    ↓
Melt Prompt
    ↓
Structured Skill
```

完成后，Skill 熔炼将从：

```text
上传文本 → AI 自己猜怎么总结
```

升级为：

```text
上传文本
→ 标记素材性质
→ 指定 Skill 目标
→ 自动匹配分析框架
→ 定向熔炼
→ 输出结构化 Skill
```

这套逻辑应作为 StoryWeaver 后续 Skill 系统的基础能力，而不是仅作为前端 placeholder 功能。
