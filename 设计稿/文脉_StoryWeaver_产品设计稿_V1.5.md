# 文脉 StoryWeaver 产品设计稿 V1.5

> 版本：V1.5  
> 日期：2026-08-04  
> 基线：`文脉_StoryWeaver_简历落地版产品设计稿.md`、前端 V1.3、后端 V1.2  
> 定位：从“单章可控闭环”升级为“现有作品可恢复、未来 1—3 章可控推进”

## 1. 版本目标

V1.5 必须让作者完成两个连续任务：

1. 把已有 TXT、Markdown、DOCX 或 ZIP 项目导入，确认章节切分和候选资产后形成可继续创作的项目；
2. 在作者确认的滚动大纲范围内，把 1—3 个章节作为队列逐章执行，每章仍独立预检、生成、审查和提交，重大剧情变化必须停下等待人工确认。

V1.5 不是自动写整本书。系统不能绕过正典、预算、审查、版本锁或人工门禁。

## 2. 核心原则

- 导入结果先进入候选区，绝不直接覆盖正典；
- 批量任务只是编排多个独立章节工作流，不允许一次模型调用生成多章；
- 队列最多 3 章，取消后保留已经独立提交的章节；
- 重大剧情门禁优先于自动推进；
- 自动局部修订默认最多改动正文 15%，必须保存修改范围和证据；
- 章节分支拥有独立正文头和状态快照，不污染 MAIN；
- 模型降级的每次尝试都可追溯模型、Prompt、Token、费用和失败原因；
- 测试 Demo 数据与生产数据严格分离。

## 3. V1.1 累积能力：作品导入

### 3.1 导入向导

流程：

```text
选择文件
→ 格式/编码检查
→ 章节切分预览
→ 调整标题与顺序
→ 提交异步提取
→ 检查人物别名和候选资产
→ 批量确认
→ 进入项目
```

状态：

```text
UPLOADED → SPLIT_REVIEW → EXTRACTING → CANDIDATE_REVIEW → COMPLETED
                                   ↘ FAILED ↔ 可重试
                    任意未完成状态 → CANCELLED
```

支持格式：TXT、Markdown、DOCX、ZIP。ZIP 只接受受控扩展名，不允许路径穿越、符号链接或嵌套压缩炸弹。

### 3.2 候选确认

候选类型：人物、别名、地点、势力、道具、能力、世界规则、历史事件和伏笔。用户可以接受、拒绝或合并；只有接受操作才写入正式业务表。

### 3.3 伏笔生命周期

```text
PLANNED → PLANTED → REINFORCED → PARTIALLY_REVEALED → RESOLVED
                                                ↘ ABANDONED
```

每次变更保存证据章节、证据文本、预计处理章节范围、变更人和版本。

### 3.4 影响分析与导出

修改旧章节后生成影响清单：事实、人物状态、后续章节、Embedding 和 Context Packet。Git 工程导出为 ZIP，目录固定为 `canon/ manuscript/ runtime/ reviews/ exports/`，禁止包含凭证。

## 4. V1.5 核心能力

### 4.1 滚动大纲

每个项目维护五层窗口：全书总纲、当前分卷、未来 10—20 章故事弧、未来 3—5 章详细章纲、下一章场景卡。提交 MAIN 章节后，只补足窗口，不重写已确认部分。

### 4.2 连续章节队列

用户选择 1—3 个尚未确认的章节，设置统一目标、视角人物和每章指令后启动。队列状态：

```text
DRAFT → RUNNING → WAITING_CHAPTER_APPROVAL → RUNNING
             ↘ WAITING_GATE
             ↘ PAUSED ↔ RUNNING
             ↘ FAILED ↔ 可恢复
             ↘ CANCELLED
             → COMPLETED
```

已完成项不可回滚为未完成；恢复从第一个未完成项开始。

### 4.3 重大剧情门禁

以下变化自动建立门禁：主要人物死亡、世界硬规则变化、主角获得核心能力、反派身份揭示、伏笔废弃、卷结局变化、单章费用超过阈值。门禁必须展示类型、证据、来源 Workflow、建议和成本；用户可批准或拒绝，操作带版本锁。

### 4.4 自动局部修订

局部修订请求必须指定 ParagraphKey 或字符范围、替换文本、理由和预期版本。后端验证范围、相邻段落和最大修改比例；超限返回 422，不自动降级为全文重写。

### 4.5 章节分支

从任意确认版本创建 `MAIN` 之外的命名分支。分支保存独立正文版本、事实快照和状态；用户可比较，但 V1.5 不自动合并事实。提升为 MAIN 必须显式确认影响分析。

### 4.6 模型降级

每个 Agent 使用有序模型链。只有可重试故障、429、超时或熔断才进入下一模型；校验失败、预算不足和内容门禁不得靠换模型绕过。页面展示每次尝试和最终采用模型。

## 5. 信息架构

项目侧栏新增：

- 导入与恢复；
- 连续生产；
- 滚动大纲。

章节编辑器新增分支面板；Workflow 状态页新增门禁、局部修订和模型尝试；模型与费用页增加降级率和采用模型分布。

## 6. V1.5 Exit Gate

```text
[ ] 四种格式至少各有一个成功导入测试
[ ] 章节切分可人工修正并可恢复
[ ] 候选资产不会直接进入正典
[ ] 可连续推进 3 章且每章独立 Workflow/提交
[ ] 重大剧情变化会暂停队列
[ ] 自动局部修订不超过配置比例
[ ] 分支正文与 MAIN 隔离
[ ] 模型降级过程可审计
[ ] 队列可取消、暂停和恢复
[ ] 前后端、迁移、E2E 和 Docker 验收通过
```

## 7. 明确不在 V1.5

- 多人评论、RBAC、企业 SSO；
- 完整 Conversation/Message/Chat 平台；
- 全文搜索和关系图；
- Skill 市场与 Mod；
- 自动合并章节分支；
- Kubernetes 和多区域高可用。
